## 建议怎样计算

每个候选在若干情景中按最新市场状态滚动执行，计算折现利润、引擎核算的社会福利、期末现金/份额/产能/韧性变化。各指标使用固定尺度乘目标权重，得到效用；最终评分为平均效用减去风险权重乘“平均效用与最差四分位样本均值之差”。少量样本的尾部指标仅用于情景比较。

搜索排名前三的非基线候选进入另一组验证情景。所有验证样本均提高所选目标、且现金和退出约束满足，才有资格被推荐；有多个通过者时取验证评分最高者。否则保留规则基线，但不能把基线本身当作风险保证。既不只凭训练最高分，也不声称连续动作的全局最优。

公司阶段目标是明示的偏好设定，不是从现实企业估计的参数。公司利益与社会福利可以冲突；资产和现金是偏好维度，不能与利润相加后解释为额外货币福利。社会福利目标控制本公司的行动；联合福利方案另行标记，不能假设其他主体会自愿接受。

## 实验结论

留出设置：种子369101/369102，2/5/10家公司，三个目标；第二个种子同时降低供应商和政府现金。预测2轮、各2个搜索/验证情景、候选上限12、总预算300步。固定参数前已记录实验约定。

- 18例中17例提高所选效用，1例因验证不够稳健保留基线，0例负效用差。它们只覆盖两个种子及指定对手响应假设，不能解释为94.4%的现实成功率。
- 公司阶段目标有4例短期利润下降，但韧性等阶段维度改善；2例总福利下降。目标效用改善不等于公司利润和福利同时改善。
- 平均绝对利润预测误差为24,925.45元（市场合成金额），说明公开先验与实际状态仍存在明显差异。推荐不使用事后真实私有状态修正选择。
- 该组最大单次计算耗时约2.75秒，实际耗时受人数、候选、轮数和诊断预算影响。这组关闭了多人诊断，不能外推为所有参数的延迟承诺。

额外滚动执行使用369601/369602两个新种子、四家公司、5轮、每轮重新规划。下表是相对同种子规则基线的变化，金额来自合成市场；利润为企业A，福利为全市场。

| 目标 | 种子369601：利润差 / 福利差（元） | 种子369602：利润差 / 福利差（元） |
|---|---:|---:|
| 公司阶段 | +64,264.80 / +18,998.90 | +44,802.17 / +74,699.14 |
| 公司利润 | +50,102.93 / +65,989.99 | +79,660.70 / +70,254.92 |
| 社会福利 | +52,306.40 / +76,197.82 | +65,450.13 / +129,932.08 |

三种目标在这两例均改善基线，福利目标的福利增益最大；公司利润目标并非每例都得到最高实际利润，说明有限候选、有限期限和对手预测仍会影响建议质量。不能从两例推导统计显著优势。

浏览器另运行种子360802规则/福利两组各5轮，福利从2,995,550.36元提高到3,127,406.16元。此例用于端到端验收，不并入预注册留出统计。

## 已验证的使用边界

在实验室可选择2—10家公司、1—10轮预测、2—8个情景、最多48个候选槽位和12000步上限。当前库23个模板，归一化后可能合并，并增加最多两个价格局部候选；48是上限，不保证生成48个不同动作。所有启用的经济机制参与结算，但未搜索动作会列明，互助/协调尚未穷举全部伙伴。

多人诊断只检验所列有限策略、期限和情景的纯策略单边偏离；预算不足返回“未完整检查”。没有证明完整动态市场的纯/混合纳什均衡存在、唯一或已找到。旧概念实验保留匹配硬币混合均衡和学习的CCE/纳什差异展示。局部囚徒困境仅在实际收益满足双方T>R>P>S时报告，不将市场自动贴标签。

没有家庭工资与跨期储蓄、现实经济数据校准，也没有无限候选或无限前瞻。供应商/消费者/政府的响应目标是模型假设；规则或目标改变后需要重算。用户此前原10元额度已保守预留9.993565元，剩0.006435元；本次新增真实模型调用0次、费用0元。本次“执行实验”指实际市场引擎的动作结算，不冒称新语言模型实验。

## 本机使用和复现

双击外层 `START_MARKET.cmd`，进入 `http://localhost:3210/`。顶部“博弈策略实验室”默认打开目标建议；“四方批量实验工作台”中企业控制选择“目标建议：公司阶段/公司利润/社会福利”，每轮保存动作依据。工作台默认2轮、2情景、8候选、200步；多人诊断在实验室按需运行。

使用 `.venv/Scripts/python.exe scripts/run_advisor_v16_acceptance.py --stage N` 按1到6顺序验收；已有证据不会被覆盖。新运行使用新的输出目录/工作副本保留旧证据。`run_advisor_v16_execution.py` 复现独立偏离审计与8局滚动执行。`verify_advisor_v16_restore.py` 用于管理脚本备份恢复前后的数据对比。
