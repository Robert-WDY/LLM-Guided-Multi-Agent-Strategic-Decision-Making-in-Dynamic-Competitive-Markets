# Stage 6.7：候选动作与边际投入修复

日期：2026-08-25。

## 1. 修复目标

本阶段严格按以下顺序执行：

1. 修复 Advisor 候选动作和 `status_quo` 定义；
2. 增加广告、服务、产能、企业韧性、共享韧性和维修的逐项边际收益检查；
3. 使用冻结真实 LLM 输出、冻结市场状态和冻结后续动作带做零 Token 验证；
4. 区分 Advisor 预测校准、市场引擎内部正确性和现实参数校准。

没有调用任何真实模型，也没有修改市场状态转移公式或 `market_v4.yaml` 参数。

## 2. 根因和版本策略

v5 的 `status_quo` 等于“当前价格 + 所有可选投入归零”。真实 DeepSeek 配对发现，风险防御人格的 Control 保留 500,000 分服务投入后，企业价值比 v5 高 85,845 分。这说明“零投入”不是普遍安全动作。

同时，旧公开候选把“增加服务 500,000”叠加在 Rule 基线的广告、服务和产能上。Advisor 实际比较的是一个混合动作，无法知道服务本身是否值得投入。

为保证历史回放，v3–v5 不做原地修改。新增 `pareto_reliable_v6`：

- Advice Schema：`public-pareto-marginal-advice-v6.0.0`；
- Advisor Model：`public-pareto-marginal-market-rollout-v2.0.0`；
- Reliability Gate：`pareto-reliability-gate-v2.0.0`；
- 旧 v5 Advice/Gate Hash 的兼容计算保持不变。

## 3. 新的 `status_quo`

v6 中，`status_quo` 不再代表机械清零，而代表：

> 当前价格 + 只保留通过单项和组合边际收益门槛的经营投入。

单项候选从零可选投入基线开始，分别只增加一项标准预算。每一项记录：

- 预期企业价值边际变化；
- 预期累计利润边际变化；
- 预期损失边际变化；
- 最坏风险调整价值边际变化；
- 人格确定性等价值边际变化；
- 是否通过单项门槛；
- 是否在组合交互检查后进入最终经营基线；
- 排除原因和防篡改 Hash。

单项进入候选池必须同时满足：预期企业价值为正、最坏风险调整价值不低于零投入基线、人格确定性等价值为正。通过单项检查后，再按确定性顺序逐项加入组合；组合若破坏任何一条门槛，该项仍被排除。这避免“每项单独有效、一起投入却过度投资”。

`profit_recovery` 和 `risk_buffer` 也从边际筛选后的经营基线出发，不再顺手删除已经证明有效的服务或广告投入。

## 4. 工程验收

- v6 的 Marginal Plan、每项 Assessment、Reliability Gate 和 Advice 都有独立 Hash；
- Gate v2 绑定 Marginal Plan Hash，`status_quo` 动作必须与计划选中动作完全一致；
- 公开预测只使用公共状态、本公司私有状态、公开 Belief 和公开 Opponent Model；
- 篡改选中服务预算、Assessment、Plan 或 Gate 会导致合同校验失败；
- API 能创建 v6 Episode，Observation 能携带 v6 建议，Advisor Replay 可完全重建；
- v3–v5 原有测试继续通过。

## 5. 零 Token 冻结实验

实验复用 2026-08-25 的五个真实 DeepSeek Control 动作。每个配对固定：第 7 轮前真实 Market State、Seed、Persona、第 7–10 轮对手动作、第 8–10 轮焦点公司动作和所有市场随机事件。只把第 7 轮 Control 动作替换成 v6 推荐并自动执行。

| Seed | Persona | v6 保留投入 | v6−真实 LLM Control 企业价值（分） |
|---:|---|---|---:|
| 1 | risk_guarded_v1 | 无 | +106,305 |
| 2 | profit_myopic | 服务、广告 | +148,600 |
| 3 | risk_guarded_v1 | 服务；门禁另加小额韧性 | +625,475 |
| 4 | profit_myopic | 韧性；同时采用利润恢复价格 | +1,079,787 |
| 4 | risk_guarded_v1 | 广告、服务 | +306,173 |

结果：5/5 非负、5/5 严格为正，平均 +453,268 分，最差 +106,305 分。原唯一负配对从 v5 的 −85,845 分变为 v6 的 +306,173 分。Advice 重建 5/5 一致、市场重复结算 5/5 一致、非法动作 0、隐藏状态使用 0。

新模型调用、输入 Token、输出 Token和费用均为 0。正式结果位于 `runs/stage6.7-marginal-candidate-repair/summary.json`。

## 6. 市场参数检查

20 个“单项公开预测 vs 同一冻结真实动作带”的方向比较中，14 个方向一致，一致率 70%。产能判断最稳定；误差主要集中于韧性及少数服务情形。六个被选中单项中也有两个在对应真实冻结动作带上方向相反，但最终完整 v6 动作仍因价格和组合效果使五个配对全部改善。

因此必须区分三个判断：

1. **没有发现市场引擎内部错误。** 同一状态、动作、Seed 和动作带重复结算完全一致，原 Replay 也通过；当前负尾部首先来自候选定义和公开预测误差。
2. **Advisor 预测仍需内部校准。** 70% 方向一致不足以宣称边际预测可靠，尤其要增加事件条件下韧性收益和服务需求响应的预测校准。
3. **现实参数最终仍需校准。** 当前广告/服务饱和尺度、消费者偏好、事故概率、韧性减损和终值系数均是版本化合成参数，没有外部实证样本。本阶段真实数据引用数为 0，所以只能证明内部一致，不能证明现实有效。

现实校准不应通过随意调参来“修复”这五个已知状态。应在 Advisor 内部门禁稳定后，使用独立现实数据估计价格弹性、投入响应、成本、事故概率和资产终值，再用未参与校准的数据做保留集验证。

## 7. 结论边界与下一步

Stage 6.7 已完成候选和 `status_quo` 修复，并通过已知五状态的零 Token 修复门禁。但它仍是自动执行证据，不证明真实 LLM 会理解并稳定采纳 v6；五个状态也是已知失败集，不是未知 Seed 泛化。

下一步不立即扩大真实调用。先做零 Token 的预测校准：按事件/无事件拆分广告、服务、韧性的符号误差，增加保守置信区间或在方向不稳时 abstain。完成后只对受修复影响的少量状态进行最多 6 次真实模型复测，再决定是否扩到未知 Seed。
