# P0 / P1 / P2 实现与验收报告

日期：2026-08-18

## 实现范围

### P0：统一执行安全

- Controller 预留本轮及最多未来两轮固定运营成本；
- 流动性危机时可支配投入为 0；
- 统一保护商品成本、履约成本、事故退款和最低单位贡献形成的价格下限；
- 连续亏损进入恢复阶段后不得继续主动降价；
- 价格上限提高至 180 元，配置加载时校验它能够覆盖最坏供应成本和事故退款安全线。

### P1：决策、计划与记忆

- `decision-support-v1.0.0`：单位贡献、保本价、保本销量、现金跑道、安全投入和战略阶段；
- `strategic-plan-state-v1.0.0`：`growth / profit_recovery / liquidity_crisis`；
- 连续两轮亏损触发利润恢复，至少连续两轮盈利才退出；
- `DecisionContext v1.2` 向模型提供确定性经营指标和当前 PlanTracker 约束；
- Agent Plan 分离预测方向 `expected_outcome` 与最低成功标准 `success_criteria`；
- `ResultAnalysis v1.3` 分离预测匹配和目标达成；
- EpisodeMemory 增加连续亏损、现金回撤、目标失败和反事实结果。

### P2：反事实与随机基准

- 每个受控 Agent 回合评估现金保护、利润恢复两个替代动作；
- 反事实固定 State、Episode Seed 和其他公司动作，仅替换目标公司动作；
- 新增可复现 `UniformRandomIntentPolicy / UniformRandomModelClient`；
- 现金为 0 时预算确定为 0，不使用无限拒绝采样；
- CLI 支持 `--opponent-policy uniform-random --opponent-seed <seed>`；
- 新增 `game_theory_agent.acceptance`，支持动作带重放和多 Seed 安全矩阵。

## 真实 Doubao 20 回合验收

Episode：`doubao-p0p2-acceptance-835703ff`，一个 Doubao Agent 对三个正式可复现随机对手。

- 20 个执行回合全部提交成功，模型 fallback 为 0；
- 连续亏损后正确进入 `profit_recovery`；
- 供应成本冲击时 Agent 主动将价格提高到安全价 96.22 元，Controller 无需二次修正；
- 终局现金 410,297.10 元；
- 总资产 664,337.72 元，排名第 2；
- 综合企业价值 605,491.40 元，排名第 2。

该实验与旧实验的随机对手动作生成器不同，因此只能作为端到端行为验收；严格改进量以固定 Seed、固定动作带重放为准。

## 最终部署冒烟

- 最终代码已在同一进程重新启动私有 Controller `8010` 与 Agent Gateway `8011`；
- 两个服务健康检查均返回 `ok`；
- Episode `p0-p2-final-smoke` 完成 5 回合，1 个 Mock Agent 与 3 个可复现随机对手共提交 20/20 个意图；
- 主 Agent 单独统计为 5/5，fallback 为 0，避免随机对手掩盖真实模型连通性失败；
- 结果包含 `agent-observation-v1.2.0`、`decision-support-v1.0.0`、`result-analysis-v1.3.0` 和两个同 Seed 反事实分支。

## 已知边界

- 反事实是单步、同随机源比较，不等价于完整 20 回合最优策略搜索；
- LLM 输出仍可能不稳定，但结构错误、超时和网络错误继续由单公司规则 fallback 隔离；
- 当前状态保存在单进程内存，横向扩容前仍需迁移到持久化存储。
