# Stage 7：最终战略市场 v6

## 1. 阶段定位

Stage 7 不原地修改已经形成历史证据的 Market v4/v5。新配置
`configs/market_v6_strategic.yaml` 通过受限、可展开的配置继承复用 v5，加载后形成
完整冻结快照和独立 Config Hash。v4/v5 的配置内容、状态序列化和历史 Hash 保持不变。

最终市场按小阶段实现和验收：

1. Stage 7.1：财务困境、破产退出、市场集中度、垄断和掠夺性价格压力；
2. Stage 7.2：阈值型冷链合作项目；
3. Stage 7.3：双边应急互助；
4. Stage 7.4：可背离的价格协调、卡特尔稳定性和监管结算；
5. Stage 7.5：多机制共同运行、信息隔离、回放和长期因果矩阵。

## 2. Stage 7.1 实现

### 2.1 公司生命周期

v6 为每家公司增加公开、可回放的生命周期：

```text
operating
→ distressed（现金低且当轮亏损）
→ exited（连续困境或现金耗尽）
```

退出是单个 Episode 内的吸收状态。退出公司下一轮：

- 不参与消费者选择和缺货转售；
- 销量、市场份额和新增经营支出为零；
- 不能广告、服务、扩产、维修或公共贡献；
- 产能账面价值按配置回收后归零；
- 终局价值只保留清算后的现金，不再把失效经营资产计入价值。

所有公司仍提交一个零支出的惯性动作，以保持联合动作、幂等和 Replay 的固定公司归属。

### 2.2 集中度和垄断

系统在每轮结算后对仍在经营的公司重新归一化份额并计算 HHI，同时记录：

- 活跃企业数量；
- HHI；
- 最大企业及其归一化份额；
- competitive / moderate / concentrated / dominant / monopoly；
- 市场势力加价信号；
- 监管压力。

`monopoly` 只在剩余一家活跃企业时出现。它是市场竞争和退出产生的结果，不是 Agent 可以直接选择的动作。

### 2.3 价格战和消费者修复

当报价低于实际单位供给成本加履约成本时，系统记录掠夺性价格公司和价格战强度。该指标不自动判定违法，只作为实验可审计信号进入监管压力。

旧市场的消费者价格信号主要比较企业相对报价。在只有一家企业时，这会使任意垄断价格的相对价格信号接近零。v6 单独加入：

```text
65% 企业间相对价格
+
35% 报价相对消费者价格锚
```

因此垄断者提高价格仍会增加 Outside Option 并降低销量。v4/v5 的旧公式不变。

### 2.4 福利代理指标

Stage 7.1 新增不直接改变现金的透明评估指标：消费者剩余代理、生产者福利、缺货社会成本和社会福利代理。名称明确保留 `proxy`，在现实数据校准前不把它表述为真实福利估计。

## 3. Stage 7.1 零 Token 因果实验

脚本：`strategic_market_v6_validation.py`；输出：
`runs/strategic-market-v6-stage71/summary.json`。

20 个共同 Seed 分别验证破产、低于成本定价和垄断加价：

- 20/20 财务耗尽企业退出；
- 20/20 退出后下一轮销量和支出均为零；
- 20/20 双寡头在一家退出后形成可计算垄断；
- 20/20 两轮战略状态和市场状态完整 Replay；
- 20/20 低于成本定价提高焦点公司份额；
- 20/20 低于成本定价降低焦点公司利润，并提高监管压力；
- 20/20 垄断加价降低销量与消费者剩余代理，并提高监管压力。

聚合结果：低于成本定价平均提高份额 `113,871 PPM`，但当轮利润平均降低
`7,780,800` 分；垄断加价平均减少 `1,329` 单销量，同时垄断者当轮利润平均增加
`15,546,503` 分。所有预设门禁通过，真实模型调用和 Token 均为 0。结果 Hash：
`sha256:aeea9749c99905c3862c5bce5d4ba9f7f6267e229ebae5b86274c96affb64a02`。

该结果证明 v6 已经形成“低价打压可抢份额但要付出利润代价”和“垄断加价提高私人利润但损害消费者”的基础冲突。它尚不证明长期打压一定能逼退正常资本企业，也不等于现实监管参数已经校准；这些属于后续长期矩阵和现实校准问题。

## 4. Stage 7.2：阈值型冷链项目

### 4.1 机制

v6 新增独立的 `threshold_project_contribution_cents`，不与共享韧性贡献混账。项目累计贡献达到800万分即成功；第4轮截止仍未达到则失败，并按20%退还各公司累计投入。成功从下一轮起提供180,000 PPM公共保护和60,000 PPM供给成本下降，所有公司受益。项目成功或失败后不再接受贡献。

项目状态、逐公司累计贡献、最后贡献、失败退款、成功/失败轮次和公共效果都进入 StrategicMarketState 与 State Hash。Controller 对项目贡献使用与其他固定支出相同的现金和末轮约束。

### 4.2 零 Token 猎鹿博弈实验

20个共同Seed、每个5轮、四个处理：

- 全部合作：四家公司各贡献200万，项目成功；
- 关键一方背离：A不贡献、其余三家各200万，项目失败；
- A单独合作：只有A贡献200万，项目失败；
- 全部背离：无人贡献，项目失败。

后续所有商业动作固定，只改变首轮项目贡献。风险信号ID会进入事件随机实体，因此四个处理必须共用同一Episode ID；早期把条件名写入Episode ID导致事件轨迹不同，产生伪处理效应，现已修复。

最终20/20满足：全员贡献成功、关键一方不贡献失败、单独贡献失败；A在其他三家都投入时选择贡献平均增加2,360,942分企业价值，而其他人都不投入时A单独投入相对不投入稳定损失1,600,000分。成功项目相对关键背离平均提高全市场企业价值13,966,906分、社会福利代理14,123,165分。80个Episode全部Replay通过，真实调用和Token为0。结果Hash：`sha256:4d00de1f3a8f05338e09e3ec8aee5e8a35d7237558f7c2a062a1cf3a7a728f12`。

这证明市场中已经存在两个均衡方向：预期他人投入时合作对私人有利，预期他人不投入时背离对私人有利。它是阈值协调/猎鹿博弈，不是现有共享韧性公共品的连续搭便车机制。

## 5. Stage 7.3：双边应急履约互助

### 5.1 机制与结算边界

阶段7.1/7.2使用的`market_v6_strategic.yaml`在证据形成后冻结；互助和后续机制由`market_v6_final.yaml`继承基线并取得独立版本与Config Hash。每家公司可以在同一轮选择一个互助对象，并分别提交供给量或请求量。只有供给方和请求方互相指名，且供给、请求都大于零时才可能成交。实际成交量取以下四项最小值：供给量、请求量、供给方完成自己订单后的真实闲置产能、请求方的真实未履约订单。单方消息、单方请求或单方供给均不改变市场。

请求方保留消费者销售额和客户关系，并按每单9,000分向供给方采购履约；供给方取得费用，承担自己的实际单位成本与履约成本，并真实占用产能。公开市场缺货转售在互助结算之后发生，因此互助不是重复创造订单。系统分别记录互助接收量、提供量、双方、单价和总费用；这些信息进入StrategicMarketState、State Hash和Replay。

互助动作已进入ActionValidator、统一决策解析器、真实模型输出Schema、观察和提示上下文。退出公司不能参与互助；无效对象或超过边界的意向由统一控制层拒绝或归零。v4/v5中这些可选字段仍不序列化，因此旧配置和历史状态不变。

### 5.2 20 Seed 配对实验

实验使用同一冻结市场、同一Seed与同一Episode ID，只改变互助动作，共四个条件：双方匹配、只有请求、只有供给、双方都不行动。冻结状态让A拥有较强客户关系但只有300单产能，让B拥有10,000单产能但较弱客户关系，以构造可由双边交易改善、又不会凭空创造资源的互补条件。

20/20匹配条件发生真实转移，20/20单方请求和20/20单方供给均为零成交。相对无互助，匹配互助平均使A多完成2,000单、利润增加2,000,000分、信誉增加10,578 PPM；B利润增加381,260分；全市场利润增加2,381,260分，缺货减少850单，社会福利代理增加4,842,918分。80个Episode全部Replay，Provider调用和Token为0。冻结最终配置后的结果Hash为`sha256:b6f7f9263593375c01a75ac395acd32e7dd20e109d3b63440ee3518e73067d85`。

该实验只证明在存在能力互补和合理费用的状态下，互助可以形成双赢；不证明所有市场状态都应互助。若供给方能以更高利润直接争夺这些消费者，拒绝互助可能更合理。这个机会成本冲突将进入后续Advisor候选动作和重复博弈实验，而不是用“合作应当发生”的提示词覆盖。

## 6. Stage 7.4：价格协调、背叛和监管

### 6.1 可背离协调

价格协调被明确标记为反竞争研究机制，而不是普通合作或现实建议。每家公司可声明一个对象与目标价，但实际`price_cents`仍独立提交。只有双方互相指名且目标价完全相同，系统才形成当轮协调记录；双方可共同遵守，也可由一方实际低价背叛。目标声明本身不改变价格、销量或现金，消费者只响应实际报价。

协调结果记录双方目标价、实际价、是否遵守、背叛方、调查概率、是否被查和逐公司罚款。每家公司初始协调信誉为500,000 PPM；遵守向1,000,000更新，背叛向0更新。本轮遵守或背叛权重为350,000 PPM。高于消费者价格锚的目标、既有监管压力和明确协调记录共同提高调查概率；被查后按基础额加收入比例扣除现金，罚款上限为罚前可用现金，因而可能导致财务困境或退出但不会创造负现金。

### 6.2 20 Seed 配对结果

冻结两家公司20,000单产能以移除容量遮蔽，使用竞争价10,000分、协调目标12,000分。20/20共同遵守被识别为`honored`，20/20由A报10,000而B报12,000被识别为`undercut_by_a`。共同遵守相对竞争平均成交价提高2,000分、未购买增加736单、消费者剩余代理减少4,452,572分；罚款前联合利润增加15,139,160分，计入监管罚款后仍平均增加9,976,504分。

低价背叛者相对遵守者平均多375,055 PPM份额和2,256,708分当轮利润，但协调信誉相对完全遵守低350,000 PPM。固定Seed中8/20个共同遵守卡特尔被查，既不是必查也不是永不查；所有被查样本产生真实罚款。60个Episode全部Replay，真实调用和Token为0。结果Hash为`sha256:7f5f398952bb63bd8990c7341b6d3dfa694666b07a201df5494aa9e2ba29cf55`。

实验说明市场已同时包含合谋私人收益、消费者损失、单方背叛诱因、信誉代价和随机监管风险。它不证明该参数下卡特尔长期稳定；长期稳定性取决于处罚强度、未来轮数、对手信誉和重复互动，将在组合市场与Advisor阶段验证。

## 7. Stage 7.5：20轮组合市场

最终组合配置同时启用共享韧性、阈值项目、双边应急互助和价格协调，并保留价格竞争、低于成本压力、随机事件、公司事故、财务困境、清算退出、市场集中度和监管结算。20个共同Seed各运行“组合策略”和“机制开启但动作不使用”的控制条件，每个Episode完整20轮，共800个市场转移。

组合策略中，A/B首轮共同遵守11,500分目标价，第二轮A以10,000分背叛；A/C每轮在真实缺货和闲置产能范围内匹配互助；A/B/C首轮共同完成800万分阈值项目并在前5轮贡献共享韧性；高成本、低现金的D在市场结算后退出。控制条件保持相同初始状态和随机命名空间，但不使用四种战略动作。

40/40长局Market/Strategic Replay通过，800轮需求闭合、现金非负；所有公开观察完全一致，对手现金、成本、事故、Persona等私有字段泄露为0。两组D均20/20退出；组合组阈值项目20/20成功、互助20/20实际成交、20/20同时观察到遵守和背叛、背叛者信誉20/20低于履约者；控制组项目20/20失败。组合组共检测到15次价格协调，最终行业韧性平均高25,576 PPM。

组合策略相对控制的终局全市场企业价值平均高115,711,176分，累计社会福利代理高114,832,983分，平均互助28,979单。这是对这套固定组合策略的条件性结果，不代表所有组合动作都优于竞争，也不能作为现实政策结论。结果Hash为`sha256:de8e0cef575f097e7b7bd8ad3380372a1f8baa5d10557e19367a265d23b2c7f1`，真实调用和Token为0。

本阶段发现，当公司在刚完成最后一轮交易后因财务状态退出，清算会把其产能立即归零，而商业状态仍正确保留该结算轮销量。旧不变量把“结算轮销量”与“清算后产能”直接比较，产生伪超卖。修复后只对刚退出的结算快照豁免这项跨时点比较；下一轮退出公司仍必须零销量、零支出，吸收状态门禁不放松。

## 8. Stage 7.6：最终市场战略建议器 v9

建议器候选空间新增阈值公共项目、双边应急互助、价格协调遵守与低价背叛，并继续保留价格、广告、服务、产能、私人韧性和共享韧性候选。所有候选都从同一公开观察和本公司私有状态重建预测市场，进行3轮、5情景的真实`MarketEnv`反事实，不读取对手现金、成本、事故、Persona或真实效用。

开发10 Seed、留出6 Seed、三人格、两个市场窗口的零Token门禁通过。开发集v9相对v7的建议器选择平均增加885,267分企业价值，部署策略相对维持基线增加429,791分；留出集对应为778,162分和405,422分，最差部署差值为0，隐藏字段泄露为0。留出集36个样本中释放12次。结果Hash为`sha256:e8b2aa26669324de551c9542696f6c85b4c77f16603f7b24a8e0a278fa659540`。

早期诊断发现价格协调背叛被建议器高估：一个样本产生3,658,586分罚款和3,255,723分企业价值损失。修复不是弱化监管，而是把价格协调候选硬隔离为`research_only_candidate_ids`；它们仍参与研究性反事实，却不能进入可执行Pareto集合。v9新增最终门禁，只有高置信、预期增值至少250,000分且最坏风险调整增益不为负的双边互助可以覆盖普通弃权。提示上下文也明确研究候选不得被LLM执行。

真实LLM只做3个冻结配对、最多6次的方向性Smoke。一次调用在模型完成后因本地序列化引用旧字段而丢失，事故被保留且没有补打；其余5次均成功并具有Provider审计。两个完整配对中，互助建议被风险防守人格采纳，三轮企业价值相对无建议增加946,624分；弃权样本未执行任何价格协调，企业价值增加108,335分。已知用量下限为输入92,690、输出3,268，合计95,958 Token，保守估算0.198452元；丢失调用的Token不可恢复，因此不得把该数字当成完整账单。该实验只是集成方向证据，不构成统计稳定性或跨模型泛化证明。

## 9. Stage 8：最终市场策略族自博弈

新增不可变策略人口：均衡竞争、激进增长、高价防守、公共韧性合作者、搭便车者、互惠应急互助、价格协调遵守、价格协调背叛和掠夺性低价压力源。后三类中的价格协调与掠夺策略被标为仅研究，不能进入生产晋级候选。每个突变策略分别面对三个相同常驻策略，并轮换四个公司位置；市场模型随Seed固定变化，每局20轮且完整Replay。

第一版错误地把策略名称写入Episode ID，而市场随机事件也使用Episode ID作为随机命名空间，导致同Seed对照面对不同事件。该版本的晋级结论作废并保留诊断摘要。修复后所有处理在同一Seed、常驻策略和焦点位置下共享Episode ID，策略身份只进入独立Trajectory ID；新开发集使用98001–98003，新留出集使用此前未打开的99201/99204。

修正后的开发集972个轨迹和留出集648个轨迹全部Replay、需求闭合、现金非负。留出集中出现120个价格战轨迹、414个含破产轨迹、77个垄断轨迹、8次阈值项目成功、640次失败、72个互助轨迹、1,553次协调遵守、290次单方背叛和1,206次监管发现。搭便车者相对全员合作首轮平均多赚2,087,825分，但长期社会福利代理平均减少67,869,899分。

## 10. Stage 9：实验驱动的 Agent 参数自迭代

只使用开发集诊断纯高价防守的失败分布：负尾部集中在价格敏感市场中的高产能公司。由此生成不可变`contextual_defender_v1`：当公开市场类型为`value_oriented`且本公司私有基础产能不少于4,000单时回退均衡竞争，其余状态采用高价防守。规则只使用公开市场字段与本公司私有字段，不读取对手隐藏状态；策略版本保存参数、来源开发Seed和Hash。

## 12. 最终市场运行入口与集成修复

前端真实实验入口现在读取`/api/health`中的配置身份。连接`market-v6-final`时，合作开关实际提交`combined_v1`，建议器实际提交`strategic_market_v9`；连接旧后端时明确降级并提示，不再把旧模式冒充最终市场。实时现场、市场结果和完成报告增加存续公司、HHI集中度、主导企业、门槛项目进度、互助成交、协调/调查、价格战强度、监管压力与社会福利代理值。

`strategic_market_v9`只允许使用公开观察进行反事实规划。当前端选择完全信息实验时，入口会显式退回兼容的`bayesian_strategy_v2`；公开信息实验才启用v9。这样既不会让v9越权读取对手私有状态，也不会出现Episode能够创建、但观察中没有任何建议的静默失效。

集成冒烟首次发现：MarketEnv与API已接受`combined_v1`，但EpisodeManifest和RoundCoordinator仍只识别`shared_resilience_v1`，因此最终市场无法从前端创建完整Episode。修复后Manifest具有`final-strategic-cooperation-v1.0.0`协议，Coordinator在通信关闭、合作结算、事件阶段与Mock行为中一致处理组合模式。新增两个PowerShell启动脚本明确加载最终配置，并只在回环地址开启本地无令牌演示入口。

最终配置API创建冒烟验证了第1轮即包含4家存续企业、活动门槛项目、启用的互助和价格协调状态。随后用1个Mock Agent加3个规则席位实际推进1轮：状态从第1轮进入第2轮，Mock动作被归因为`agent-intent:mock-company_A`，其记忆新增1轮，下一轮公开观察继续生成`strategic_market_v9`建议，三类最终市场机制仍处于可审计状态。该端到端检查没有调用真实模型。后端全套321项测试通过；前端Lint、生产构建和5项渲染/演示市场测试通过。
