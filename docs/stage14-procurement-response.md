# 企业采购响应与未见参数风险验证

日期：2026-09-07。完成上一阶段指定的下一步：采购响应、退出风险与未见经济参数实验。新增策略工程可运行，但未通过默认推广门槛，**继续使用原 v11 默认配置**。本阶段无模型调用，新增费用0元；此前保守累计估算仍为1.093593元，原总预算10元。

## 实现

新增 `market/procurement_policy.py`，提供有明确输入边界的采购规划：自身所需数量、自己上一轮采购比例、公开供应商报价及当前可供量、存续买方数。不会读取其他企业现金、订单或供应商成本，也不读取未来冲击。

在5%比例网格上，先最大化预计到货量，再降低预计采购费用；预计可供量采用“公开总容量/存续买方数”的均分启发式，不能当作其他企业的真实订单。差异在1%以内时保留原比例，减少微小波动引起的切换。`capacity` 允许直接调整，`gradual` 每轮最多调整25个百分点。

`build_rule_action` 增加显式 `rule_procurement` 开关，退出企业仍执行冻结动作。新策略的模式与计划Hash随动作记录，完整实验计划包含输入、预计到货量、预计费用和实际分配比例。跨轮状态取自已有采购结算记录，保存恢复后相同状态产生相同动作。旧配置没有该开关，因此行为保持不变。

仅供研究的配置为 `configs/market_v11_procurement_research.yaml`；它不由默认启动脚本加载，不属于本机前端已启用的推荐版本。实验脚本直接比较五个策略，不会覆盖人类或LLM已提交的采购动作。

## 预注册设计与门槛

- 开发：6参数组×8种子×5策略，共240场。
- 留出：6未见参数组×12独立种子×5策略，共360场。
- 每场自然运行20轮，总计600场、12000轮，无模型调用。
- 对照为始终绑定经济供应商、最低报价采购、两家各半；候选为容量响应和分步响应。
- 各半采购是主要风险比较基线。开发组选择候选，并在留出开始前将选择结果落盘；留出结果不能反向替换候选。
- 每场完整回放，并在第8轮对恢复状态的下一步与未中断结果比较；同参数/种子配对的供应商冲击相同。

开发参数包含基准、10%报价步长、容量偏移、报价上限120%、固定报价、投入品成本占比55%。留出包含3%和15%步长、反向容量偏移、可靠性反转、较低初始现金/较高固定成本，以及复合压力。

开发和留出必须同时满足以下门槛，才允许默认推广：福利增量中位数≥0、最差值≥−5%、最差10%样本均值≥−2%、额外退出配对数为0，并通过工程门禁。

归一化福利增量 = 配对福利差 / max(对照累计福利绝对值，初始买方总现金)。下表百分数使用此分母；不是企业利润率或现实投资收益率。CVaR10为最差向上取整10%样本的经验均值，没有总体置信保证；同一种子出现在不同参数组，不能把全部配对当作独立样本。

## 失败分析

复合压力同时包含：投入品成本占比70%、供应商容量7000/10000、可靠性65%/88%、初始进价2000/2800分、成本1650/2000分、报价步长12%。所有负福利样本和额外退出都在这组，不能据此认为其中单个参数就是唯一原因。

对7个负福利或额外退出种子的两种策略，额外执行14次逐轮复核（280轮，非新增独立样本），最终Hash全部与原实验完全一致。最差种子150205中，capacity使公司B/D在第8轮因持续经营困境退出；当轮进价3513分，固定成本前单位贡献仅518分。各半采购下D到第11轮才退出，进价3106分，单位贡献1160分。该例显示，为提高预计到货量而接受更高进价，会挤压固定成本和现金缓冲。其他失败局也出现负单位贡献后现金耗尽。该归因来自机制和结算路径，不是对现实市场的因果识别。

新策略的明确缺陷：以“数量优先”替代完整经营目标，没有把自身毛利、固定成本覆盖及现金生存期纳入排序，也未预测采购分布对下一轮供应商报价的反馈。固定调整幅度限制不足以解决这一点，在复合压力组还可能延迟避险。
