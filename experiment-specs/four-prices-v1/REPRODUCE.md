# 复算四家店的结果

从仓库根目录，使用项目 Python 环境（NumPy、SciPy、scikit-learn 1.8.0），按上一阶段固定的 EconEvals 检出设置 ECONEVALS_ROOT。所有经济收入均为模拟，真实模型在本地运行。没有使用商业额度。原生市场内部的分转换为模拟元。EconEvals 为作者函数的四个独立卖方扩展。预约服务使用同一需求骨架，加入逐期容量、流失与固定成本，并直接使用外部市场已有的建议器权重。三者都限于定价。

离线验证运行 `python scripts/four_prices/validate.py`。它从提交的9个分市场/人格压缩文件核对全部配对，并以保存的原始真实模型结果重建每组首末种子的全部路径（包含服务端独立抽样组）。`summary.json` 含全部、独立解码、原人格、陌生人格与随机人格结果；每个数列是均值及按种子配对重抽的1.25%和98.75%界。whole-run 和 once 不能混合比较。价格均值及同价比例只对同轮在营企业计算。风险探针先选择公司和合同，在整组其他人照旧的情况下仅撤掉这一家公司这一个合同的建议，并放任后来所有公司继续运行。累计利润从共同第19轮按 .99 折现；单次机会从预定检验轮折现。

复现推理需要此前固定的 SmolLM2-1.7B Q4_K_M 文件（SHA-256 见 model.json），llama.cpp build b10976，loopback 端口19943。启动 `llama-server -m PATH --alias smol --host 127.0.0.1 --port 19943 -c 8192 -np 8 -ngl 99 --cache-ram 0`。顺序执行下列脚本，脚本均在 `scripts/four_prices/`：
1. `prices.py` 和 `sampling_check.py`。模型在准确限定的9个数字 token 上返回概率，所有合法 token 施加相同偏移以消除合法集合外的概率质量。市场政策要么逐合同由后端实际独立抽取，要么由同一真实模型的完整概率向量与独立均匀数精确抽取。各竞争者独立，同一竞争者在不同政策中使用共同随机流。
2. `run.py --workers 8`。可按种子恢复，产生本机 runs/four-prices-v1 的逐局记录。四位经理的参考价会随己方已结算利润、销量与价格变化；人格不改变市场结算。无候选使用当轮对手动作或隐藏人格。三位对手过去公开报价以在营竞争者中位数汇总。经理看自己的销量与利润，建议器只能读草稿、时钟和公开价格。
3. `saturation_report.py`、`subgroups.py`、`tail_replay.py`、`seat_rotation.py`、`validate.py`。后两类干预复核可能遇到新的真实模型请求；数据库中的新增响应也保存在归档内。种子对应市场独立单位，不能把同一条市场路径的多家企业或多轮报价当独立样本。

每个市场/人格文件的 paths 包含 keep（保留当期自主草稿）、greedy（控制随机性）、inf/dir + 安装数（推断型/直接估值）、skip + 安装数（撤掉一个预抽合同）以及 once/once_direct。每个合同记录草稿、当前可执行原价、最终申请与选择。每一轮的4行依序为已执行价格、销量、利润、营收、期初活跃、期末活跃。另外记录市场消费者剩余和未满足需求；预约场景未定义受容量限制后的消费者剩余。风险归因见 tail.json，匹配重放见 tail-replay.json。单轮营业利润含市场规则记录的全部费用；原生市场计入库存和供给约束，少卖的订单不能直接等同于本企业缺货。费用和消费者福利均不能外推为现实企业交易。


## 全量真实后端结果

在 PowerShell 中设 `$env:FOUR_PRICES_ALL_LIVE='1'`，重跑 run、saturation_report、subgroups、tail_replay、seat_rotation、plot_loss、validate。主报告采用 `experiment-results/four-prices-v1/live/`。原始混合口径保存在其父目录。计算模型表时共同抬高全部九个合法 token 的分数，并核实返回的概率和为 1；从概率表抽样使用同一权重，但不能保证和不同推理批次重新计算的概率完全一致。全量后端复核消除了对此数值相等假设的依赖。复算单个分支使用原始回包即可，无需联网。开启全量模式重做采集时，会优先复用先行批次已直接采样的108个市场。

额外的直接数字报价检验运行 `python scripts/four_prices/open_price.py`，从持续运行的本地模型获取24个未使用种子的报价和反事实续报并做离线抽检。
运行 `loss_audit.py` 可复算全部合同方向与损失分布；运行 `verify_diagnostics.py` 可验证最差案例及同种子穷举身份的额外路径。
